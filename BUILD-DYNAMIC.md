# MPVKit dyn6 dynamic macOS frameworks

Versions and source hashes are unchanged from dyn5. Fourteen frameworks are compiled from release sources; FriBidi, uchardet and libbluray are freshly linked from pinned PIC archives. MoltenVK, HarfBuzz 15 and the permissive archives remain individually hashed retained inputs. Their complete source-to-object correspondence has not been newly established. The historical addendum is retained separately, not asserted as current validation.

## Source build and exact recipe

The round-2 source build root is `/Volumes/4M2/Dev/rushdeck/tmp/fork6/round2-build`; its independent durable derivation is `/Volumes/4M2/Dev/rushdeck/mpvkit-dyn6/round2`. These recipes deliberately reject dyn2–dyn5 roots. Their original tags remain authoritative for historical builds and relinks. `tools/fork6/prepare.py` documents fresh input-cache materialization; root-relative tool manifests must match the actual prepared tools. No prior TLS, FFmpeg, placebo or mpv build output is copied as a source-build input.

Run `/usr/bin/nice -n 10 /usr/bin/python3 -B source/tools/fork6/build_all.py all` with `FORK6_BUILD_ROOT` set to the source-build root. All phases and architectures run serially, make/Meson use `-j2`. This single pass produces `framework-stage/{arm64,x86_64,universal}` and `candidate-Dynamic`. FFmpeg uses `ffmpeg-build`, mpv `mpv-build` and `mpv-prefix`; there are no v3/v4 path substitutions after building. The recipe is committed before the pass; the artifact commit has the identical recipe blobs and a single parent, dyn5 c920cef. The pre-build recipe snapshot is retained locally for provenance.

GnuTLS has an empty system-priority-file configure argument (`DISABLE_SYSTEM_CONFIG=1`); its sysconfdir/localedir and mpv's actual MPV_CONFDIR lie under `/System/Library/RushDeck-Disabled`. No such directories are created. Upstream `GNUTLS_SYSTEM_PRIORITY_FILE` environment handling is unchanged. On ordinary customer systems the previous build-root config path did not exist. Synthetic decode/headless comparisons test that case, not manually configured developer machines.

All fresh source compilations receive prefix maps. GMP receives its file-prefix map through CPPFLAGS, so generated `__GMP_CFLAGS` does not embed the root. TLS and the other fresh source-library links use `-Wl,-oso_prefix,<build-root>/`: this preserves debug maps while making N_OSO object references relative, rather than dropping all debug data. No shipped binary is subsequently stripped or edited to remove strings. Install-name rewriting and ad-hoc signing are framework assembly operations as before. The three retained-PIC framework links keep the dyn5 arguments: no absolute N_OSO root was present, and libbluray must retain its dyn5 bytes.

The four TLS binaries must have zero whole-slice byte occurrences of `/Volumes/`, `/Users/`, `/opt/homebrew/`. Inventories include both section-oriented `strings -arch` and complete byte counts, also covering `/usr/local/` and `/etc/`; section-only counts cannot establish absence of debug-map paths. FFmpeg configuration argv and mpv option strings are build provenance and intentionally retain actual build paths. FFmpeg `Headers/config.h` carries that same configuration and the header-only FFMPEG_DATADIR; generated files are not hand edited. Libmpv may retain its Swift N_AST debug-module reference, which is inventoried separately.

## Bound tools and durable derivation

The root-relative tool manifest and separate host payload manifest are verified during source building. Host binding covers the fixed Python 3.14 interpreter/framework, non-test standard-library source and native extensions, Meson source modules, tool executables and their transitive absolute Homebrew dylib dependencies. Meson startup and re-invocations disable bytecode reads using a protected, absent pycache prefix and `-B`; `.pyc`, standard-library test data, documentation and unused GUI/tooling modules are excluded. The PATH contains only the copied tools and macOS system tools. Apple SDK/compiler and system Python remain host prerequisites; this is a bound M3 toolchain, not a hermetic fresh-machine reconstruction.

`tools/fork6/derive_durable.py BUILD_ROOT NEW_DURABLE_ROOT` copies the committed source and the explicit input/output-prefix list, including the relative ffmpeg-source link. It converts links into relative internal links and rebases active `.pc`, `.la`, and cross `.ini` metadata only in the new copy. Its log enumerates every rewritten file and link. Original ZIP payloads stay byte exact; compiler logs, generated config headers and binaries retain their actual build provenance. Probe files and synthetic private keys are excluded.

`tools/fork6/record_relink_inputs.py BUILD_ROOT` records the framework templates, actual shared/PIC/header inputs and libbluray source verification payload used by framework assembly. Relink verification uses that manifest, not Meson/Python 3.14/Ninja/NASM/pkgconf or the source-build host manifest. The relink uses system Python and Apple linker/SDK/signing tools.

For an independent relink, use absent `relink-stage`, `relink-Dynamic` directories, set `FORK6_RELINK=1`, `FORK6_STAGE=relink-stage`, `FORK6_DYNAMIC=relink-Dynamic`, and run build_frameworks.py for arm64, x86_64, then --combine. The complete process tree must run under the logged sandbox-exec invocation and Seatbelt profile denying file reads/writes on mpvkit-dyn, mpvkit-dyn2, mpvkit-dyn4, mpvkit-dyn5, and the entire rushdeck/tmp tree. Use temporary data inside the durable root. Denied controls read only BUILD-DYNAMIC.md in those four old fork copies and the own source-build copy; the durable copy is a positive control. Compare all 18 regular Versions/A Git blobs plus the complete Dynamic tree (regular files, symlink contents, Git modes), and verify strict signatures for all architectures. This is framework assembly with three PIC links, not another upstream source compilation.

Native C acceptance compares dyn5 with final dyn6 bytes using synthetic MP4/MXF/H.264 decode digests, headless decode choices, and a synthetic localhost TLS1.3 trust/roundtrip test. No x86_64 runtime or GUI rendering claim is made. Probe-bundle compliance runs lgpl_check --release, which directly starts that isolated bundle's ffmpeg and ffprobe helpers with -buildconf; it does not start the RushDeck main executable. No installed application or Companion is used.

## Open limits

Inherited Libplacebo `/Users/runner/.rustup/.../*.rs` and `.cargo/registry/.../*.rs` strings are Rust diagnostic/panic source provenance, not shaderc paths. The retained LuaJIT archive embeds module search paths including `/Users/runner`, `/usr/local/share/lua/5.1` and `/usr/local/lib/lua/5.1`; mpv enables Lua, while RushDeck disables external scripts. Libmpv's macos-bundle-path defaults include Homebrew/usr-local executables, applied for MPVBUNDLE=true. The protected compiled config path is not a general environment sandbox.

Libbluray retains the dyn5 `/usr/local/lib/` dlopen search for libaacs/libbdplus. This is a genuine runtime code-search path, reachable for Blu-ray inputs, not build provenance. Its binary is intentionally unchanged from dyn5. Whether the player should retain libbluray requires a separate coordinator/user decision. PIC source correspondence, retained-archive search paths, Homebrew host prerequisites and missing Intel runtime coverage remain limitations.
